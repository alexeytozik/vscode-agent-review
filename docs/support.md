# Поддержка и проверки

Поддерживаемый путь: локальный VS Code 1.96 или новее, одна папка workspace, публичные Webview/WorkspaceEdit/TextDocument API и подтверждённые lifecycle `apply_patch`. Основной интерфейс — полная вкладка ревью; `changeReview.view=editor` сохраняет публичные CodeLens и команды. ON/OFF, команды и настройки `changeReview.*`, publisher `alexeytozik` и восстановление v2 сохранены. Shell/Python/MCP записи не считаются подтверждёнными правками.

CI содержит Linux/macOS × minimum 1.96.0/stable и проверку установленного VSIX. Это матрица настроенных проверок; локальный отчёт не утверждает, что удалённый CI запускался. Windows, Remote SSH, WSL, containers, virtual/multi-root workspaces и web editor не объявлены поддержанными. Расширение не запускается в недоверенном workspace.

`npm test` проверяет текущие runtime-модули: модель, восстановление, guards, hooks/config, renderer transport и DOM. `npm run test:editor` проверяет настоящий изолированный редактор; с `REVIEW_VSIX=/absolute/path/package.vsix` дополнительно устанавливает пакет только в тестовый профиль. `REVIEW_EDITOR_VERSION=1.96.0` выбирает minimum, по умолчанию stable. `REVIEW_VSCODE_EXECUTABLE` выбирает уже установленный бинарник.

`npm run test:renderer` автоматически запускает отдельный редактор и присоединяется к его webview: реальная CSS, темы, размеры/zoom, keyboard/focus/AX, Keep/Undo. `npm run test:performance` измеряет большие допустимые файлы и очередь, layout/heap/long tasks и реальные действия. Для обоих достаточно `npm ci`: pinned `playwright-core` управляет Chromium внутри VS Code, отдельный browser download не нужен. На Linux используй `xvfb-run -a`. Отчёты и screenshots сохраняются в `output/`; в VSIX их нет. Тайминги зависят от машины; проверки текста, решений, количества пересылок и достижимости не заменяются порогом времени.

Migration-only: `bridge.js`, `extension.js`, `install.py`, `install-native.py`, `review-native.mjs`, старые `media/review.js`/`review.css`. Эти файлы исключены из VSIX и не входят в загрузку `review.js`. Они остаются в репозитории для проверки и восстановления старых частных патчей. `npm run test:migration` отдельно запускает четыре JavaScript suite старых bridge/native модулей. Python installer checks (`test/install.test.py`, `test/native-install.test.py`, `test/installer-cases.test.py`) требуют старую проверенную сборку: vendor `26.1007.21434` либо VS Code `1.141.0`/`1.143.1`; новый редактор они не патчат. Их количество не прибавляется к проверкам текущего runtime. `npm run test:all-unit` запускает оба JavaScript набора. Старые Python integration runners и `test/run-checks.py` относятся к прежней интеграции; для актуального продукта используются npm scripts выше.

Private workbench patches, внутренние notification handlers и app-server capture не являются поддерживаемой установкой. Live harness требует отдельного явного разрешения: использует авторизацию и лимит реального аккаунта. Обычные проверки работают с синтетическими данными и отдельными home/profile, не меняют настоящие hooks, trust или рабочий редактор.
