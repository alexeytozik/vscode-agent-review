# Установка Preview

Нужны VS Code 1.96 или новее и Codex с поддержкой lifecycle hooks (`PreToolUse`, `PostToolUse`, `UserPromptSubmit`, `Stop`). Подключение работает с локальными файлами, одной папкой workspace и одним окном ревью на workspace. Проверки ведутся для Linux/macOS; Windows, Remote SSH, WSL, контейнеры и веб-редактор пока не объявлены поддержанными. [Поддерживаемый путь и разделение тестов](support.md).

Установи VSIX через Extensions → Install from VSIX. Открой папку проекта и запусти **Agent Review: Connect**. Расширение добавит свои обработчики в `hooks.json` внутри `CODEX_HOME` (по умолчанию `~/.codex`), сохранив чужие хуки и локальную резервную копию. Содержимое редактора и расширения Codex не меняется.

Перезапусти сессию Codex. В Codex CLI с тем же `CODEX_HOME` открой `/hooks`, проверь и разреши новые хуки. Для IDE доверие настраивается через тот же CLI; разрешение не обходится автоматически. После изменения определения хука Codex снова потребует его проверить. Поддержка протокола проверяется реальным запросом; неизвестные форматы не принимаются за подтверждённые правки.

После запроса сама открывается отдельная вкладка **Agent Review** с полным файлом. Сверху только имя файла, номер правки и число оставшихся правок в нём, стрелки и **✓ Keep** / **× Undo**. Keep оставляет выбранную правку, Undo возвращает исходный текст. После решения показывается следующая правка, затем следующий файл этого запроса. Кнопки постоянно доступны сверху, без ожидания наведения. `Alt+]` и `Alt+[` переключают правки, `Ctrl+Alt+Y` / `Ctrl+Alt+N` (`Cmd+Alt+Y` / `Cmd+Alt+N` на macOS) оставляют или откатывают их. Закрытие вкладки не удаляет очередь; **Agent Review: Open** открывает её снова. Старые запросы доступны командой **Agent Review: Review Queue** в палитре команд. При перезапуске незавершённое ревью возобновляется, если включены ON и автоматическое открытие.

Вкладка использует обычный публичный API VS Code и не требует патчей редактора. Старый интерфейс в обычных файлах доступен через настройку `changeReview.view: editor`; по умолчанию стоит `review`. Основной переключатель ON/OFF остаётся прежним. Тема и шрифт берутся из VS Code; код занимает всю доступную область без карточки и поясняющих подписей. Вкладка показывает файл целиком, включая неизменённые строки и все ожидающие правки. Это просмотр текста, без редактирования и подсветки синтаксиса обычного редактора. Выбранная правка выделена, Undo/Keep относятся только к ней. Стрелки прокручивают к следующей правке; можно выбрать её щелчком по изменённому блоку. Текст не сокращается, длинные строки доступны через горизонтальную прокрутку. При конфликте показан сохранённый снимок, а решения заблокированы. Актуальный файл можно открыть обычным способом; после его исправления очередь обновляется автоматически.

Внизу только два режима: **Review: ON** и **Review: OFF**. Клик всегда переключает режим, даже если подключение ещё не готово. OFF закрывает вкладку и пропускает новые запросы: можно писать сколько угодно без ручного принятия. Старые нерешённые правки сохраняются; после включения их можно открыть через **Agent Review: Open**. Если включить ревью посреди запроса, оно начнёт собирать правки со следующего запроса. Сочетание `Ctrl+Alt+Shift+R` (`Cmd+Alt+Shift+R` на macOS) делает то же самое.

ON означает включённый режим. Значок предупреждения и подсказка при наведении отдельно сообщают, если нет подключения или получение событий ещё не подтверждено. Для подключения запусти **Agent Review: Connect**; для подробностей — **Agent Review: Integration Status**. Предупреждение не мешает выключить режим одним кликом.

Ревью происходит после записи файла: это кнопки Keep/Undo, а не запрос разрешения перед записью. В очередь входят только подтверждённые изменения через `apply_patch`, включая вложенный вызов из `exec`, если runtime доставил его события. Прямые записи из Python или shell не превращаются в правки с Keep/Undo; для командных операций показывается предупреждение о неполном покрытии. Уже пропущенные правки задним числом не восстанавливаются. Неоднозначный контекст, изменения через команды или MCP, бинарные файлы, символьные ссылки и секретные файлы требуют отдельной проверки. Если файл изменился вручную, расширение сохраняет непересекающиеся изменения, а конфликтующий откат останавливает. Смена BOM и смешанные окончания строк требуют ручного отката. Лимиты: 1 MiB на файл и 40 MiB на сохранённую очередь. Патчи больше лимитов пропускаются с предупреждением.

Снимки и очередь хранятся локально в хранилище VS Code; своей сетевой отправки у расширения нет. По умолчанию исключены `.env` и его варианты, `auth.json`, `credentials.json`, `.npmrc`, `.netrc`, `.pypirc`, `.pgpass`, `kubeconfig`, `token.secret`, `secrets.yaml`/`secrets.yml`/`secrets.json`, `.docker/config.json`, ключевые файлы и каталоги `.ssh`/`.aws`/`.kube`/`.gnupg`. Это проверка пути, а не поиск любых секретов в тексте. Решения собираются в одну сводку для следующего запроса той же сессии: количество оставленных и отменённых правок, имена файлов для повторного чтения. Сама сводка попадает в контекст Codex, как и другой контекст этой сессии.

Количество `kept/undone` считается по блокам: одиночное решение, действия для файла/запроса и Accept All учитывают каждый разрешённый блок одинаково. Accept All оставляет готовые правки; ошибки и ещё выполняющиеся запросы остаются в очереди. При сбое доставки уже сохранённые решения ждут повторной отправки, в том числе после перезапуска. Каждое новое решение получает отдельный ID, который сохраняется при повторе доставки.

После сохранённого решения ненужный текст снимка удаляется из JSON и памяти. Для повторных событий остаётся ограниченная история: до 512 завершённых запросов, 4096 ID операций и 256 KiB. Нерешённые снимки этим ограничением не вытесняются. Повреждённая очередь восстанавливает валидные соседние записи и сохраняет исходный файл перед новой записью. Временная ошибка чтения требует повторного чтения оригинала и не заменяет его пустой очередью.

Если Undo изменил файл или буфер, но не смог сохранить решение, исходный снимок остаётся. При восстановлении проверяются точный текст, путь и права файла; поздние ручные изменения не переписываются. После неудачного сохранения буфера нужно явно сохранить или восстановить его. Незавершённый Keep после перезапуска требует повторного решения. **Agent Review: Discard Saved Snapshot** удаляет выбранный снимок, оставляя текущие файлы как есть.

Дополнительные исключения задаются в `changeReview.exclude`, например `["private/**", "**/*.secret.txt"]`. Шаблоны относятся к корню workspace, учитывают dotfiles и используют `/`; до 128 шаблонов по 1024 символа, без абсолютных путей, `..` и отрицания `!`. Встроенные исключения нельзя отменить отрицательным шаблоном. Обычные YAML и `terraform.tfvars` остаются доступны; `.gitignore` сам по себе их не исключает. Для файлов с секретами под другим именем добавь свой шаблон. При смене правил соответствующие снимки и транспортные payload удаляются из ревью, файлы проекта остаются как есть; причина пропуска видна без содержимого. Повреждённые старые архивы, сохранённые для восстановления, очищаются отдельно и не считаются новыми захваченными снимками.

Если расчёт diff превышает лимит сложности, приостанавливается только этот файл. Причина видна в его ревью, Keep/Undo недоступны, снимок сохраняется. Повторное открытие, обновление и перезапуск не запускают тот же неудачный расчёт заново. Остальные файлы можно проверять как обычно; автоматического отката целого сложного файла нет.

Повреждённые события и записи решений изолируются в `lifecycle/event-quarantine` и `lifecycle/feedback-quarantine` внутри хранилища расширения. Каталоги имеют права `0700`, обычные файлы — `0600`. Каждый карантин хранит не более 32 записей и 25 MiB содержимого; крупные payload и старые записи удаляются, причина сохраняется в пределах этих 32 записей. Символьные ссылки не читаются. Это правило касается только повреждённых сообщений, а не нерешённых правок. После пропуска события ON показывает неполное покрытие, в том числе после перезапуска: проверь затронутые изменения вручную. Новые валидные события продолжают доставляться. Временные ошибки чтения или обработки оставляют сообщения для повторной попытки в исходном порядке.

Сводка решений сначала полностью подготавливается; записи удаляются только после успешной локальной записи JSON в stdout обработчика. Ошибка чтения, подготовки или stdout сохраняет валидные решения для следующего запроса. За раз выдаётся до 2000 решений, остаток остаётся на следующий запрос. Повреждённая соседняя запись не скрывает валидные решения. Сбой процесса после вывода, но до удаления может повторить сводку: одинаковый `Review batch` обозначает тот же набор решений, его не нужно учитывать дважды. После частичного удаления может повториться только оставшаяся часть с другим ID. Подтверждения от получателя контекста нет: успешная запись stdout не доказывает, что модель получила сводку, и не даёт гарантии exactly-once. Формат количества kept/undone и списка файлов сохранён; как и прежде, текст списка ограничен 4000 символами. Решения другой сессии не потребляются.

Pending tool snapshots, недоставленные события и сводки решений не удаляются по возрасту: короткий PreToolUse-процесс уже мог закончиться, пока сам инструмент ещё работает. Они переживают перезапуск и неверные часы. Новый ключ snapshot включает сессию, запрос и tool ID; старый ключ читается для миграции. У записей есть время создания. Неподтверждённый источник нужен позднему PostToolUse и восстановлению после сбоя, поэтому его отсутствие не объявляется успехом capture. Повреждённые prepared snapshots изолируются отдельно в `pending-quarantine` с теми же private limits, что у других карантинов.

Автоматическая уборка касается только временных staging-файлов с PID завершившегося writer-процесса. PID активен или неизвестен — файл остаётся; возраст файла не служит доказательством. Уборка запускается при старте и не чаще раза в пять минут, читает до 256 directory entries и удаляет до 32 drafts за проход. Курсор продолжается на следующем проходе.

**Agent Review: Clean Up Local Data** сначала показывает категории и количество данных. Можно отдельно удалить временные drafts, tool snapshots, недоставленные события, сводки, карантин или recovery backups. Для transport/feedback/backups сначала нужен Disconnect и явное подтверждение выбранной категории. Очистка tool snapshots прекращает capture ещё работающих инструментов; очистка сводок удаляет также durable outbox. Один пакет обходит до 2048 entries, следующий продолжает обход. Активные writer drafts, файлы проекта и нерешённые review snapshots не удаляются.

**Agent Review: Show Local Diagnostics** открывает локальный JSON для просмотра и ручного копирования. В нём только версии, флаги настроек, количества, последние timestamps/тип результата, состояние собственных хуков и известные лимиты. Исходников, prompt, переменных окружения, команд хуков, exclusion patterns, session IDs и приватных путей в отчёте нет. Он не отправляется и не копируется автоматически. Это снимок текущего окна, без полного runtime timer.

**Agent Review: Disconnect** убирает только обработчики расширения. Сохранённая очередь остаётся. После отключения новые правки не собираются.

Новый Connect использует пять общих обработчиков для всех подключённых папок. Отдельный локальный реестр выбирает активное окно по canonical root; для вложенных папок выбирается самый глубокий root, включая OFF. Одну папку нельзя одновременно подключить в двух окнах или профилях. Закрытие окна удаляет только его активную запись; явный Disconnect удаляет регистрацию папки. Общие обработчики убираются после Disconnect последней зарегистрированной папки, включая ранее закрытые окна. Чужие hooks сохраняются.

Старые обработчики отдельных workspace продолжают работать до явного Connect в соответствующем окне. Он переносит только проверенную собственную команду в общий реестр. После смены команды используй обычное `/hooks` и доверяй только просмотренному обработчику. Автоматического изменения доверия нет. Реестр и bootstrap находятся в `review-hooks` внутри текущего хранилища CLI; исходники и prompt туда не записываются.

# Переход с локальной версии 0.5.x

У Preview идентификатор `alexeytozik.agent-review`. Команды и настройки `changeReview.*` сохранены. Очередь автоматически копируется из хранилища `local-tools.change-review`, когда новое хранилище пустое. Не запускай обе версии одновременно.

Сначала отключи или удали старую версию. Старый патч Codex восстанови до установки Preview: `install.py restore --extension ...` работает только с проверенной резервной копией. При отсутствии подходящей копии переустанови расширение Codex из официального источника. Preview его не патчит.

С версии 0.7.0 основной интерфейс — отдельная вкладка ревью. Ранее установленная локальная интеграция `install-native.py` в этом режиме не используется. Подключение к хукам, сохранённые очереди и решения остаются прежними.

Старый патч самой VS Code можно убрать командой `python3 install-native.py restore --app '/Applications/Visual Studio Code.app'`, если скрипт подтверждает сборку и резервную копию. При несовпадении файлов восстанови приложение из официальной установки. После восстановления полностью закрой VS Code через Quit и открой снова. Новый VSIX сам файлы редактора не меняет; для обычной вкладки ревью патч не нужен.

# Сборка и проверки

Node.js 22 или новее. `npm ci`, `npm test`, `npm run package`. VSIX собирается стандартным `@vscode/vsce`. `npm run test:editor` скачивает исходный VS Code и проверяет работу публичных элементов управления; на Linux нужен `xvfb-run -a npm run test:editor`. `npm run test:live` выполняет один настоящий запрос через установленный Codex CLI и существующую авторизацию, в отдельном профиле. Он использует лимит твоей подписки. `REVIEW_AGENT_CLI` позволяет выбрать исполняемый файл CLI. `REVIEW_LIVE_TRANSPORT=app-server npm run test:live` проверяет сервис IDE и передачу сводки следующему реальному запросу. Live-проверки разрешают только свои обработчики в отдельном временном профиле; настройки доверия пользователя не меняются.

Публикация выполняется отдельно: нужно зарегистрировать или подтвердить Marketplace publisher `alexeytozik`, проверить настройки пакета и явно запустить публикацию. Подготовленная сборка сама ничего не публикует.
